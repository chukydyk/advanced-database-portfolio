======================================================================
D4  Query routing: targeted (one shard) versus scatter-gather (every shard)
======================================================================
events WHERE hotel_id = 2 AND ts >= Sep 2026 (key prefix)  -> SINGLE_SHARD shards: shard1rs
events WHERE hotel_id IN (1, 5) (hotels in both zones)     -> SHARD_MERGE  shards: shard1rs, shard2rs
events WHERE type = 'noise_alert' (no shard key)           -> SHARD_MERGE  shards: shard2rs, shard1rs
guest_profiles WHERE _id = 100 (hashed key, equality)      -> SINGLE_SHARD shards: shard2rs
guest_profiles WHERE email = ... (no shard key)            -> SHARD_MERGE  shards: shard1rs, shard2rs
guest_profiles WHERE _id between 1 and 50 (hashed key, range) -> SHARD_MERGE  shards: shard1rs, shard2rs

Targeted queries touch one shard and scale with the cluster. Scatter-gather queries touch every shard,
so the shard key must match the main access pattern. Range queries on a hashed key cannot be targeted.
